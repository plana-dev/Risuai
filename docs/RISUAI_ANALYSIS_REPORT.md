# RisuAI 프로젝트 분석 보고서

## 1. 프로젝트 개요
RisuAI는 Svelte 5(Runes)와 TypeScript를 기반으로 구축된 크로스 플랫폼 AI 채팅 애플리케이션입니다. Tauri를 통해 데스크톱 애플리케이션으로 패키징되며, 웹 및 모바일 환경에서도 동작하도록 설계되었습니다. 이 프로젝트는 다양한 LLM(Large Language Model) API와의 연동, 정교한 캐릭터 설정(Tavern 카드 호환), 그리고 플러그인을 통한 높은 확장성을 특징으로 합니다.

## 2. 시스템 아키텍처

### 2.1 기술 스택
- **프론트엔드 프레임워크**: Svelte 5 (최신 반응형 시스템인 Runes 사용: `$state`, `$derived`, `$effect`)
- **언어**: TypeScript
- **빌드 도구**: Vite
- **데스크톱 런타임**: Tauri
- **상태 관리**: Svelte 5 Runes 및 `svelte/store` (Writable Store) 혼용
- **데이터베이스**: IndexedDB, OPFS (Origin Private File System) 등을 활용한 로컬 스토리지 추상화

### 2.2 디렉토리 구조 및 역할
- **`src/lib`**: UI 컴포넌트 라이브러리. `ChatScreens`(채팅 화면), `Setting`(설정), `SideBars`(사이드바), `UI`(공통 UI 요소) 등으로 구성되어 뷰 레이어를 담당합니다.
- **`src/ts`**: 핵심 비즈니스 로직이 집중된 영역입니다.
    - **`process/`**: 채팅 생성, 프롬프트 엔지니어링, API 요청 처리 등 AI 관련 코어 로직.
    - **`storage/`**: 데이터베이스 및 파일 저장소 관리.
    - **`model/`**: 각 AI 서비스별 모델 정보 및 파라미터 정의.
    - **`plugins/`**: 외부 스크립트 실행 및 확장 API 제공.
    - **`characterCards.ts`**: 캐릭터 카드(PNG/JSON) 파싱 및 내보내기 로직.

## 3. 핵심 기능 구현 상세

### 3.1 AI 엔진 및 통신 시스템 (`src/ts/process`)
AI 엔진은 사용자의 입력과 설정을 바탕으로 프롬프트를 구성하고, 외부 API와 통신하여 응답을 받아오는 핵심 모듈입니다.

- **API 요청 디스패치 (`request.ts`)**:
    - `requestChatData` 함수가 중앙 제어 장치 역할을 합니다.
    - 사용자 설정(모델, 파라미터)에 따라 적절한 핸들러(OpenAI, Claude, Oobabooga 등)로 요청을 분배합니다.
    - 네트워크 오류 시 자동 재시도(Retry) 로직과 대체 모델(Fallback)로의 전환 기능이 구현되어 있습니다.
    - 플러그인에 의한 요청/응답 가로채기(Intercept) 및 변조를 지원합니다.

- **스트리밍 및 도구 호출 (`openAI.ts`, `request.ts`)**:
    - OpenAI 및 호환 API의 경우 SSE(Server-Sent Events)를 통해 텍스트를 스트리밍합니다.
    - `fetchNative` (Tauri 환경) 또는 표준 `fetch`를 사용하며, 응답 스트림을 `TransformStream` 파이프라인을 통과시켜 실시간으로 텍스트를 디코딩하고 UI에 전달합니다.
    - **Tool Calls (Function Calling)**: AI가 외부 도구(웹 검색 등)를 호출해야 한다고 판단하면, 실행 결과를 처리한 후 다시 AI에게 결과를 주입하여 최종 답변을 생성하는 재귀적 호출 로직이 구현되어 있습니다.

- **프롬프트 엔지니어링 (`prompt.ts`, `templates/`)**:
    - 채팅 내역, 캐릭터 페르소나, 시스템 프롬프트, 로어북(Lorebook) 등을 조합하여 최종 컨텍스트를 생성합니다.
    - Jinja2 템플릿 엔진을 지원하여 복잡한 지시문(Instruct) 템플릿을 동적으로 렌더링할 수 있습니다.
    - 토크나이저를 통해 컨텍스트 윈도우 크기를 계산하고, 제한을 초과할 경우 오래된 메시지를 정리하거나 요약하는 로직이 포함됩니다.

### 3.2 캐릭터 및 자산 관리 시스템 (`characterCards.ts`)
RisuAI는 업계 표준인 Tavern 카드(V2)와 확장 규격(V3)을 모두 지원하며, 이미지 파일 내에 메타데이터를 숨기는 방식을 사용합니다.

- **PNG 청크 파싱**:
    - PNG 파일의 바이너리 데이터를 읽어 `tEXt` 또는 커스텀 청크에 숨겨진 캐릭터 JSON 데이터(V2/V3 스펙)를 추출합니다.
    - 대용량 이미지 처리를 위해 제너레이터 기반의 스트림 읽기를 지원하여 메모리 효율성을 확보합니다.

- **자산(Assets) 처리**:
    - 캐릭터 표정(Emotion), 배경, 첨부 파일 등의 자산은 `ccdefault:`나 `__asset:`과 같은 내부 프로토콜 URI로 매핑됩니다.
    - 외부 공유를 위해 캐릭터 카드 내보내기 시, 관련 자산들을 Base64로 인코딩하여 단일 이미지 파일이나 커스텀 포맷(`charx`)으로 패키징하는 기능을 제공합니다.

### 3.3 채팅 시스템 및 렌더링 (`ChatBody.svelte`)
프론트엔드에서는 백엔드에서 처리된 데이터를 시각적으로 표현하고 사용자 상호작용을 처리합니다.

- **마크다운 및 번역**:
    - 메시지는 마크다운 파서를 통해 HTML로 변환됩니다.
    - 자동 번역 기능이 활성화된 경우, HTML 렌더링 전 또는 후에 번역 엔진(LLM 또는 외부 API)을 거쳐 텍스트를 변환합니다.
- **동적 이미지 매칭**:
    - 메시지 텍스트 내의 이미지 태그나 키워드를 분석하여, 캐릭터에 등록된 표정 자산이나 배경 이미지와 동적으로 매칭하여 표시합니다.

### 3.4 상태 관리 및 스토리지 (`stores.svelte.ts`, `database.svelte.ts`)
- **Svelte 5 Runes**: 전역 상태(`DBState`, `selIdState` 등)는 `$state` 룬을 사용하여 반응형으로 관리됩니다. 이는 데이터 변경 시 UI 업데이트를 효율적으로 트리거합니다.
- **데이터 영속성**: 브라우저 환경(IndexedDB)과 데스크톱 환경(파일 시스템)을 추상화하여, 어느 환경에서든 동일한 인터페이스로 데이터를 저장하고 불러올 수 있습니다.

### 3.5 플러그인 시스템 (`plugins.ts`)
- **API V2/V3**: JavaScript 실행 환경을 샌드박스 형태로 제공하거나(제한적), 사용자 동의 하에 시스템 API에 접근할 수 있는 구조입니다.
- **훅(Hook) 시스템**: 프롬프트 생성 전(`replacerbeforeRequest`), 응답 수신 후(`replacerafterRequest`), UI 렌더링 시점(`editdisplay`) 등 다양한 생명주기에 개입하여 기능을 확장할 수 있습니다.

## 4. 주요 동작 흐름 (Operational Flows)

### 4.1 채팅 메시지 생성 흐름
1.  **사용자 입력**: 사용자가 채팅창에 메시지를 입력하고 전송합니다.
2.  **트리거 및 전처리**: 등록된 스크립트나 트리거가 있다면 입력값을 검사하거나 변형합니다.
3.  **프롬프트 구성 (`prompt.ts`)**:
    *   현재 캐릭터 정보, 대화 내역, 로어북 등을 불러옵니다.
    *   토크나이저를 통해 모델의 최대 컨텍스트 길이에 맞게 내용을 자릅니다.
    *   설정된 템플릿(Jinja 등)을 적용하여 최종 API 페이로드를 생성합니다.
4.  **API 요청 (`request.ts`)**:
    *   설정된 AI 모델(OpenAI, Claude 등)로 비동기 요청을 보냅니다.
    *   스트리밍 모드일 경우, 청크 단위로 데이터를 수신하여 즉시 파이프라인으로 보냅니다.
5.  **후처리 및 렌더링**:
    *   수신된 텍스트에서 '생각(Thought)' 블록이나 특수 태그를 파싱합니다.
    *   `ChatBody.svelte`에서 마크다운을 렌더링하고, 필요 시 번역을 수행한 뒤 화면에 표시합니다.
    *   완성된 메시지는 로컬 DB에 저장됩니다.

### 4.2 캐릭터 임포트 흐름
1.  **파일 선택**: 사용자가 PNG 또는 JSON 파일을 선택합니다.
2.  **포맷 판별 (`characterCards.ts`)**:
    *   이미지 파일인 경우 `PngChunk` 리더를 통해 메타데이터를 스캔합니다.
    *   `CharX` 포맷인 경우 압축을 해제하여 구조를 파악합니다.
3.  **데이터 정규화**: V2, V3, 또는 구형 Tavern 포맷 데이터를 내부 `character` 인터페이스에 맞게 변환합니다.
4.  **자산 저장**: 캐릭터에 포함된 표정이나 추가 이미지를 `assets` 스토리지에 저장하고, 해당 ID를 캐릭터 데이터에 매핑합니다.
5.  **DB 등록**: 최종 변환된 캐릭터 객체를 `DBState`의 캐릭터 목록에 추가하고 영구 저장소에 씁니다.

### 4.3 플러그인 실행 흐름
1.  **초기화**: 앱 실행 시 `loadPlugins`가 호출되어 DB에 저장된 활성 플러그인들을 로드합니다.
2.  **스크립트 주입**: 각 플러그인의 코드가 실행되며, `getV2PluginAPIs`를 통해 제공되는 안전한(Safe) API 객체를 주입받습니다.
3.  **이벤트 리스닝**: 플러그인은 특정 이벤트(메시지 수신, 렌더링 등)에 핸들러를 등록합니다.
4.  **실행**: 해당 이벤트 발생 시 등록된 핸들러가 실행되어 데이터 변조나 UI 조작을 수행합니다.
